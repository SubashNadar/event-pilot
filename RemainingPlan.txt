## 1. Chatbot Interface and Planning Workflow

Build an interactive chatbot interface that guides users through a planning process.

### Requirements
- Create a clean, responsive chat interface with a message history.
- Support user messages and AI assistant responses.
- Display a step-by-step planning workflow.
- Provide suggested options or clickable buttons for common inputs.
- Include one custom text input field so users can enter their own answers.
- Allow users to move through the planning steps conversationally.
- Maintain the user's responses throughout the planning process.
- Display loading indicators and appropriate error messages.

### LangGraph Orchestration
- Reuse the existing LangGraph event-planning workflow instead of replacing it with direct LLM calls.
- Model the chatbot's planning conversation as explicit state: collected inputs, missing fields, current question, validation errors, and readiness to generate.
- Route the conversation through LangGraph nodes for input validation, follow-up-question selection, brief summarization, and final plan generation.
- When all mandatory inputs are complete, pass the validated brief to the existing specialist-agent, manager, review, and bounded reflection workflow.
- Preserve graph state with the chat session so a resumed conversation continues at the correct planning step.
- Trace the conversation and planning graph runs in Langfuse, without exposing private chain-of-thought.

### Input Collection and Validation
- Identify the information required to generate a complete plan.
- Check whether the user's inputs are sufficient before generating the final plan.
- If any required information is missing or unclear, ask relevant follow-up questions.
- Present suggested answers wherever appropriate, while allowing custom input.
- Avoid repeatedly asking questions that the user has already answered.
- Once all mandatory information is collected, summarize the inputs and generate a structured plan.
- Allow the user to review or refine the plan.

## 5. Guardrails and System Prompts

Implement suitable system prompts and guardrails to improve safety, reliability, and response quality.

### System Prompt
Define the chatbot's role, objectives, workflow, response style, and constraints. The chatbot should:
- Guide users through the planning process.
- Collect and validate the required inputs.
- Ask clarifying questions when information is insufficient.
- Use retrieved context for knowledge-based answers.
- Maintain continuity within the current conversation.
- Generate clear, structured, actionable plans.
- Be transparent when information is missing or uncertain.

### Guardrails
- Validate incoming requests and required input fields.
- Detect missing, invalid, or contradictory planning inputs.
- Prevent the chatbot from inventing facts, retrieved sources, or completed actions.
- Treat retrieved documents and user-provided content as data, not as instructions that can override system-level rules.
- Defend against prompt injection and attempts to override system instructions.
- Apply output validation and handle malformed LLM responses.
- Enforce relevant access controls and session ownership on the backend.
- Apply suitable rate limits and input-size limits.
- Handle LLM failures, vector database failures, and timeouts gracefully.
- Avoid exposing API keys, credentials, internal prompts, or private conversation data.
- Keep safety checks separate from normal planning logic where appropriate.
